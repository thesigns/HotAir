# AGENTS.md

Guidance for AI agents working on this repository. The game design is in `docs/HotAir-GDD.md`; controls are in `README.md`.

## Project overview

Hot Air is a calm hot-air balloon game: fly as far from the launch field as the propane allows, steering only by height (every height has its own wind), and land softly on dry, flat ground. Score = distance in metres × the landing multiplier (EXCEPTIONAL ×1.5, GOOD ×1, ROUGH ×0.5, CRASH ×0). Low-poly 3D, a mobile-first browser game: portrait on phones (a phone held sideways gets a "turn your phone" card and the flight pauses), landscape only on a computer. The target host is GitHub Pages. A sister project of *Tram* (`../Tram`, repo `thesigns/Tram`) – same rules and many patterns carried over. Current state: **M2** (GDD §14) – three countries, each with its own record per propane preset: the Netherlands (the polder: ditches, roads, canals, farms, windmills, cows, villages, greenhouses, power lines, the North Sea coast), Italy (Tuscany: rolling hills, irregular fields, vineyards, olive groves, cypress drives, hilltop towns) and Switzerland (valleys with rivers, roads, lakes, villages and chalets, pine woods, rock and snow, cable cars, winds channelled along the valleys); other balloons with AI pilots; the flight model; the wind ladder; settings and help; the soundscape. Not done: dikes.

## Technical rules

- **Vanilla JS + ES modules, no bundler and no npm.** Three.js `0.160.0` from jsDelivr via the `importmap` in `index.html`. Don't add a build step or `package.json` unless explicitly asked.
- **Fonts** (GDD §12.1): Grandstander from Google Fonts (700, 900) for the logo, headings, buttons and HUD popups; the system font stack `ui-rounded, system-ui, …` for everything small. Numbers that change use tabular figures (`font-variant-numeric` in CSS, fixed digit cells – `Hud.digits` – on the canvas).
- **`index.html` must stay in the repo root.** Everything else goes into subfolders. All paths are relative.
- **No PWA** until the user asks for it; no fullscreen request.
- Everything is **in English**: UI text, code comments, docs.
- Code style: 2 spaces, semicolons, single quotes, brief comments only where something isn't obvious. Scratch objects used in hot loops live at module level.
- Tuning belongs in `js/config.js`. The flight model must keep matching the GDD §5.1 table – check with `node tools/feel.mjs` after any change to `BALLOON`, `ATMOS` or `PROPANE`; whole flights over many seeds with `node tools/fly.mjs [flights] [height]`.

## Models (Blender)

- Every model is built from code in **`tools/blender/models.py`** (the source of truth – don't edit `assets/models/models.blend` by hand and expect it to survive) and written by `tools/blender/build.py`:
  `"E:\Programy\Blender Foundation\Blender 5.2\blender.exe" --background --factory-startup --python tools/blender/build.py -- [preview-dir]`
  It writes `assets/models/models.glb` (one object per model), `assets/models/models.blend` and **`js/models/dims.js`** (generated: footprints, wall and ridge heights per collision part, tree sizes, the windmill's hub, the pylon's conductors). With a preview directory it renders contact sheets with EEVEE (not Cycles) – look at them after every change.
- Conventions in Blender: the origin on the ground at the model's centre, the front facing Blender −Y (= +z, south in the game), metres; buildings reach 3 m below the origin (a plinth) so they stand on slopes. Colours are materials from `PALETTE`; low poly, flat; keep the many-times models cheap (trees, cows), `*_low` variants for woods and far chunks.
- In the game, `js/models/library.js` loads the GLB before the world (main.js), turns materials into vertex colours and keeps each model as a flat triangle list; `Builder.model()` (js/world/kit.js) merges them into the chunks, turned by a yaw and scaled. Only the windmill (it turns into the wind) and its sails, and the balloon's basket, are meshes of their own (`modelGeometry`). The balloon's envelope is built in code (its gores take the pattern).
- The generators place buildings with `place()` / `footprint()` (js/models/place.js, pure): a prop to draw (`b.props`) and collision boxes from the dims (`b.houses`), turned by a quarter-turn yaw. Hills put a building on the highest ground under it (`Hills.building`).
- Two detail levels (`DETAIL`): chunks farther than `near` get the cheap trees (only every other tree of a wood), no cows and – in the hills – a coarser ground grid; they are built again in full when the balloon comes within `upgrade`. Keep a whole view around 600k triangles.

## Conventions

- Units: meters, seconds, radians, kelvin. Y is up, **−Z is north, +X is east**. Headings are clockwise from north: a heading `h` points along `(sin h, 0, −cos h)`; an object facing it has `rotation.y = −h`. Wind directions are meteorological (where the wind comes **from**); the air moves towards `dir + π`.
- Gameplay logic doesn't import Three.js, so it runs in Node: `js/core/balloon.js` (the physics), `wind.js`, `flight.js` (phases, landing, rating, the ladder, the pibal, power lines), `fleet.js` (the other balloons), and the terrains as data: `js/world/polder.js`, `hills.js` (the base of the hilly countries), `tuscany.js`, `alps.js`. `js/world/world.js` (`makeWorld(country, seed)`) makes a country's winds and terrain – main.js and the tools both use it.
- **Countries** (`COUNTRIES` in config.js): name, difficulty, sky and haze colours, the far ground, the winds (merged over `WIND`) and the terrain kind (`polder` | `tuscany` | `alps`). Records are per country × preset (`progress.country`, `progress.preset`).
- **The terrain interface** every country implements: `height(x, z)`, `surfaceAt(x, z)`, `near(x, z, r)` (trees and houses), `wires(x, z)` (`{ cross, h, spread }` – power lines and cable cars), `sounds(x, z, r)`, `launch`, `coast` / `coastS()` / `landRange()`, and optionally `channel(x, z, y, W)` (bends the wind: the Alps' valleys). Houses may stand on a slope (`h.y`, `h.sink`); `roofAt` adds `h.y`. A touchdown's closing speed includes the ground rising under a balloon carried against a hillside (`groundRate`). Landings among vines, olive trees, rocks or trees are ROUGH at best. Rendering lives in `js/world/polderView.js`, `props.js`, `js/models/balloon.js`.
- **The flight model** (`Balloon`, GDD §5): envelope temperature → buoyancy against weight and quadratic drag, with the envelope's air and added mass in the inertia. `y` is the basket floor (altitude). The burner heats (fading near `tMax` – the natural ceiling), the envelope cools towards the air, the vent cools fast. The pressure falls off with `ATMOS.scaleHeight` (compressed, so flying high costs more propane – the main trade-off). Propane is counted in seconds of burning; the balloon gets lighter as it burns. With the propane gone, BURN gives `BALLOON.vapour` of the heat – a ROUGH landing, not a crash.
- **The flight** (`Flight`): phases `launch` (tethered) → `air` ⇄ `ground` (a touchdown; climbing above `GROUND.hop` again is a hop) → `done` | `crashed`. The distance is measured **at the touchdown** (the drag adds nothing). The rating uses the hardest touchdown since the balloon was last clearly airborne. Water under the basket at a touchdown or during the drag, a house, or more than `LANDING.crash` is a CRASH; ending in the trees is ROUGH. VENT on the ground deflates; the crew ends the flight after `GROUND.crew` seconds anyway. Events go to `onEvent` (liftoff, touchdown, hop, reserve, empty, done, crash).
- **The other balloons** (`Fleet`, GDD §6.3): the same `Balloon` physics with simple pilots (pick a height, hold it, change it, land after a while; unlimited propane – kept topped up so the mass stays normal). Courtesy rules near the player: an AI balloon above doesn't sink, one below doesn't climb – a collision is the player crossing another balloon's height. Each balloon is an ellipsoid from basket to crown (`gap()`); `hit()` ends the flight, `threat()` gives the earliest collision course within `FLEET.warn` s (contact time, or closest approach for a near miss) for the HUD. A balloon that drifts beyond `FLEET.recycle` comes back in the haze on a course that crosses the player's path at a nearby height. Balloons near the player feed the wind ladder.
- **Power lines** (`Polder.power`, `wires`; GDD §7): along some roads, pylons every `POWER.spacing`, three sagging wires. `touchesWires()` tests the balloon's profile (basket, ropes, envelope radius by height) against them; `predictWires()` looks 30 s ahead with the present velocity for the HUD warning. Pylons are obstacles of kind `pylon`.
- **The coast** (`coastFor`, GDD §8.1): chosen from the seed and the start wind – usually downwind, sometimes behind, sometimes none. Along one axis: sea blocks (the beach, then the sea), one dune block (rolling `height()`, pines), and the coast road behind it; lines across the coast end behind the dunes (`landRange`). `coastS()` is the signed distance (> 0 out to sea).
- Block kinds (`kindOf`): sea, dunes, village (houses round the sides, a church), glass (greenhouses – obstacles of kind `glass`), forest, fields (strips, farms, windmills of kind `mill`, cows).
- **The wind ladder** (`flight.ladder`, one entry per `LADDER.bin` m): learned from the pibal and from the balloon's own height. Arrows are drawn relative to `flight.ref` – "away from the launch" – so they don't spin with the camera.
- **The polder** (`Polder`): square blocks (`POLDER.block`) between border lines whose type (road, canal, ditch) depends on the line index only, so roads run straight for kilometres. A block is a wood, or field strips across one axis separated by narrow ditches, maybe a farm (yard at the end of a strip, house and barn) and rows of trees along its roads. Everything is axis-aligned and deterministic from `hash(seed, i, j)`; block (0, 0) is the launch block (a pasture strip, roads all round). `surfaceAt`, `near` (trees and houses) and `height` are what the landing and collisions use. Later countries get their own terrain class with the same interface.
- **The hilly countries** (`Hills`): things are kept by the block (`HILLS.block`) they stand in, since a block's things may stand in its neighbours (a cypress drive, a town, a cable car crossing blocks – its `owner` draws it); a block is complete once it and its neighbours are filled (`block()`, `ensure()`). No eviction (the content would be duplicated). Tuscany: rolling fBm hills flattened at the launch and on the hilltop towns, Voronoi-like fields (`site()`, the type cached per site), woods and groves as cheap `low` trees, vine rows as runs. Alps: valleys along x (`centre(k, x)`, `where()`), floors, walls up to ridges with passes, lakes, rivers and roads as ribbons, cable cars kept clear of the slope.
- **Rendering the hills** (`HillsView`): a height grid (`HILLS.cell`) coloured per triangle by `terrain.color(x, z, slope)`, plus the things through the shared kit (`js/world/kit.js`: the builder, unit shapes, `drawTree`, `drawHouse`, `drawCow` – the polder view uses it too). A chunk is built by a generator, a step at a time within `HILLS.budget` ms per frame.
- **Rendering the polder**: chunks of `POLDER.chunk²` blocks, each a group with one merged vertex-coloured mesh (double-sided Lambert) plus the windmills' sails (shared geometry, turned by `PolderView.animate` with the surface wind), built one per frame around the balloon within `POLDER.viewRadius`, dropped beyond. Water is drawn slightly below the fields, with banks; the sea lower still, with a far sea plane in `main.js`.
- **Balloon models** (`js/models/balloon.js`): 12 envelope patterns (`PATTERNS`, the first is the player's); the basket, people and burner are one shared merged geometry, so a balloon is a handful of draw calls. Only the player's has the glow light.
- Simulation runs at a fixed 60 Hz step; rendering interpolates the balloon position.

## Mobile view and controls

- `resize()` in `js/main.js` moves the optical centre with `camera.setViewOffset` (40% from the top in portrait). The HUD canvas is laid out for a 390 px phone and scaled up on bigger screens (`VIEW.hud*`).
- BURN and VENT are held buttons (`js/core/input.js`, Pointer Events with pointer capture, so both thumbs work at once). Camera gestures only on the game canvas: one finger orbits, two pinch, a double tap resets. The default camera follows the ground track; after a drag it stays where the player put it (GDD §10).

## Testing

- Start the dev server with `python tools/serve.py 8766` – it sends `Cache-Control: no-store`, so changed modules always load (`python -m http.server` lets Chrome cache them; if that happened, use another origin such as `127.0.0.1` instead of `localhost`). Tram uses 8765. **Don't use port 8080.**
- `node --check` doesn't treat a `.js` file as a module here: copy it to a `.mjs` file to syntax-check it.
- Tools: `node tools/feel.mjs` (the flight model), `node tools/fly.mjs [flights] [height] [country]` (whole flights), `node tools/traffic.mjs [flights] [country]` (the other balloons).
- `?debug` shows a state readout and exposes `window.hotair = { game, input, sound, camera, cam, flight, balloon, polder, wind, view, startFlight }`; `?seed=N` repeats a world. Measure with console scripts instead of judging by eye (`input.burnKey = true` holds the burner).
- To check the phone layout, inject a 390×780 `<iframe>` into a page from the same server that doesn't run the game itself (e.g. the `/docs/` listing).
- Test on a real phone early (GDD §14).
- The console must stay clean.
